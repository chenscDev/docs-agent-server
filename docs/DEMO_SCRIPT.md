# 演示脚本（Demo Script）

两版口述：**约 30 秒**（投递 / 群面开场）、**约 3 分钟**（面试深讲或录屏旁白）。  
操作路径默认：真机 Debug 包 → `docs-agent` → 已有一份 ready 文档（可用 `eval/corpus/acme_handbook.md`）。

---

## 演示前 Checklist（2 分钟）

- [ ] 后端已起：用仓库 `.venv` 跑 `run.py`（或 F5），`/health` 为 ok；业务请求带 `API_TOKEN`  
- [ ] 真机 Host / Token 指向电脑，能上传、能聊天  
- [ ] 知识库至少 1 份 `ready`（建议员工手册语料，问题好讲）  
- [ ] 网络正常（千问 Key 可用）；关闭会弹无关通知的 App  
- [ ] 预演一遍：上传（可选）→ 提问 → 点引用 → 停一次生成 → 历史抽屉  

**推荐演示问题（按顺序）：**

1. 「试用期是多久？」→ 必出引用  
2. 「产假一共有多少天？」→ 展示拒答（手册未写）  
3. （可选）「报销时限？」→ 多要点 + 引用  
4. （可选，讲 P2/P3）拐弯抹角问法 → 空检索会**改写 query 再搜**；追问「那个上限呢」→ **指代改写**  
5. （必做一次）点「停止生成」→ cancel 打断 LLM，气泡落 `已停止` / cancelled

## 版本 A：30 秒（电梯稿）

**口播（可背）：**

> 我做了一个文档问答 Agent：用户上传 PDF/Markdown，后端切分、Embedding、FAISS 检索；模型通过 Function Calling 调 `search_docs`，再流式返回答案。  
> 端上是 RN 分包，用 SSE 区分「正在检索」和「出字」；答案带可点击引用，点开再拉 chunk 全文。  
> Key 只放服务端；还有 requestId 和 25 题评测方便复盘。

**屏幕上只需闪过：** 聊天页出字 → 一眼工具卡/引用 → 点进 Citation（可剪辑加速）。

**不要在 30 秒里讲：** 表结构、chunk 参数、和 FAISS 生产差距。

## 版本 B：3 分钟（标准面试演示）

### 时间轴

| 时段 | 你说什么 | 你点什么 |
|------|----------|----------|
| 0:00–0:25 | 场景：企业内部制度问答，要可溯源、少幻觉 | 打开 App 首页聊天 |
| 0:25–0:50 | 文档要先 ready 才能搜；状态机 pending→…→ready | 知识库列表扫一眼 status（或快速上传已备好的 md） |
| 0:50–1:40 | 提问；先 tool 再 delta；空命中会改写再搜 | 问「试用期是多久？」；指工具轨迹 → 流式字 → `[1]` |
| 1:40–2:10 | 引用不塞全文，点开二次查 chunk，省流量、对齐主键 | 点引用进 Citation |
| 2:10–2:35 | 手册没有的就拒答；点一次停止看 cancelled | 问「产假多少天？」；中途停一次生成 |
| 2:35–3:00 | 工程点：多 KB、多 Token、增量 FAISS、解析 recover、双路径同编排 | Settings / 气泡 `req=…`；可闪历史会话 |

### 口播全文（可微调，勿照念过长）

> 这个项目解决的是「基于私有文档的可信问答」。客户端是 React Native 动态分包，推理和服务端 Agent 在 FastAPI。  
>  
> 文档上传后走状态机：解析、切分、Embedding、写入按知识库隔离的 FAISS；只有 ready 才能进检索，避免半成品被搜到。  
>  
> 用户提问时走 SSE：先 `message.accepted`，模型若需要就 Function Call `search_docs`；若首轮空命中，服务端会改写 query 再搜一次（仍有次数上限），端上能看到工具开始/结束；然后再 `delta` 出字，最后 `completed` 带 citations 和 usage。  
>  
> 引用里的 chunkId 和数据库主键对齐，点开再请求全文——这是 UI 二次查询，不是模型自己又问一轮。  
>  
> 文档里没有的内容我会演示拒答。历史只带最近若干轮，上轮检索结果不默认带入，控制成本和串味。  
>  
> 另外做了多知识库、多 Token 鉴权、FAISS 增量索引、解析队列重启恢复、流式/非流式同一 Agent 编排，以及错误码、requestId、25 题固定评测（含多轮追问）。和线上差距主要是单机索引、进程内队列非分布式、无多租户，下一步可换 RQ/Redis 和权限。

### 被追问时的 3 个短答

| 问题 | 一句话 |
|------|--------|
| 和 ChatGPT 套壳有啥区别？ | 手写 tool loop、自定 SSE、FAISS+SQLite 分工、引用对齐与拒答，端上只是壳。 |
| 为什么正文不放向量库？ | 单一事实来源在 SQLite；FAISS 只做相似度，避免元数据漂移。 |
| 怎么评估效果？ | 固定语料 25 题 + 关键词/拒答/followup 粗判，失败记 FAILURE_CASES。 |

## 演示翻车预案

| 现象 | 立刻怎么做 |
|------|------------|
| 连不上 API | 改 Host / 确认同一 Wi‑Fi；切到电脑 `curl /health` 证明后端活着 |
| 一直 parsing | 换已 ready 的文档继续讲状态机，后台再查日志 |
| 模型慢 | 先讲「tool.started 已反馈在检索」，等 delta；备非流式 curl 录屏片段 |
| 无引用 | 仍可讲 fallback/citations 解析；换推荐问题 1 |
| 拒答失败（乱编产假） | 坦诚是 Prompt/召回问题，引出评测与改进，不硬圆 |
